# file-in path (#14)

> headspace gains a file-in path: a copy-in that mirrors export's discipline, so a network-disabled workspace can receive a non-trivial payload (issue #14)
> instruction: verified by the `success_signal` run (c22/h1): embodiment's case end-to-end with --network disabled on shipped verbs only

## Audience

- agent runtimes and operator tooling driving headspace as a CLI; the first consumer is agentculture/embodiment's live adversarial probe, which needs a network-disabled workspace to receive a multi-file harness

## Before → After

- Before: delivering code into a workspace requires argv (`ARG_MAX`-bounded, recorded verbatim in `outcome_summary`, provenance.inputs, journal.jsonl, state.json) or a host HTTP server reachable only with --network enabled — so network isolation and non-trivial payloads are mutually exclusive (issue #14, measured on 0.9.0/docker 29.1.3)
- After: a network-disabled workspace receives a non-trivial, multi-file payload through a first-class copy-in (headspace put, run --input) whose recorded trace is path+digest only — the host-HTTP-server workaround and argv smuggling are both dead

## Why it matters

- closed-by-default is the product's core posture, and today its most secure setting is its least usable one: the gap pushes exactly the adversarial/untrusted-code callers isolation exists for into weakening it (--network enabled) just to deliver their own code

## Scope / boundaries

- --allow-host-path keeps failing closed: policy.resolve() (policy.py:263-267) refuses a filesystem scope the engine cannot enforce, and issue #14 explicitly endorses that refusal ('the refusal is right'); the copy-in fills the gap the refusal leaves, it does not weaken the mount posture
  - instruction: change nothing in policy.resolve(); add a regression test pinning the `policy_denied` refusal for --allow-host-path on docker and asserting `_sealed_kwargs` still contains no binds
- the closed default stays: no caller environment is forwarded absent an explicit --env/--env-file — issue #13's own probe (seven image defaults, nothing of the caller's) is pinned by a regression test as the no-flag behavior
  - instruction: add the regression test replicating the issue's probe (caller-set marker variable, no flags, assert absent and env count matches image defaults) on both providers
- env is per-job only: run-level flags, the shortest secret lifetime the CLI can offer; create grows no --env and nothing is baked into the workspace or its anchor container
  - instruction: no create-side changes; document the per-job lifetime in run's help and the explain catalog; verify live that the job container (the value's engine-side holder) is removed after run completes
- copied-in files are inputs, not artifacts: they live in their own ledger in state.json, render distinctly in the result package, and never feed the destroy guard — the guard protects unexported \*products\* (artifacts.py inventory), and a host-sourced input is re-puttable by definition
  - instruction: a separate inputs ledger key in state.json; renderers list it distinctly; the destroy guard keeps reading only the artifact inventory
- the no-value-recording guarantee covers headspace's own recording; a job that prints its environment writes the value into captured output, which persists in state.json's job record and journal — a documented limitation with a warning in run --help, because a guarantee that overclaims is worse than one that states its edge
  - instruction: add the warning sentence under --env/--env-file in run --help and the explain catalog; assert the surface-class split in the recording test
- an --env value's engine-side residue: the job container (which holds the env) is removed best-effort in run's finally (docker.py:918-924, suppressed exceptions by design); a lost race leaves a labeled stray until remove() reaps it — documented, with destroy as the guaranteed reaper
  - instruction: keep the finally-removal as is; assert normal-path removal in the live test; document label-reaping as the backstop in the run docstring
