# Delivery Summary — file-in path (#14)

plan: `file-in-path-14` · run: `complete` · date: `2026-07-29`
baseline: `devague summary skeleton`

## Intent

Close the two gaps `agentculture/embodiment` filed against headspace 0.9.0. There
was no way to get a **file** into a workspace ([#14][i14]) — `--allow-host-path`
fails closed on Docker, correctly, which left a network-disabled workspace unable
to receive its own code — and no way to pass a **secret** ([#13][i13]), because
argv was the only channel and argv is recorded verbatim in four durable places.
The run executed the converged `file-in-path-14` plan: 14 tasks in 5 dependency
waves, fanned out to parallel agents in isolated worktrees, each merge TDD-gated
by the main agent.

## Mid-work Decisions

- `d1` — merge `t1` after `t4`/`t5` rather than at the end of wave 1 — t1 tightens
  the `@runtime_checkable` `Provider` protocol, but `DockerProvider` only satisfies
  it at t4/t5, so merging on plan order would have left the suite red across two
  waves and made the TDD gate meaningless mid-run. Execution order unchanged; only
  the merge point moved.
- `d2` — the main agent reconciled two signature divergences at merge time instead
  of re-dispatching: `sha256` → `expected_sha256` (matches `export_artifact`), and
  `fake.stop()` returning `StopOutcome` instead of raising. t1 and t3 built the two
  halves of one seam concurrently and diverged despite identically pinned briefs.
- `d3` — serialized every live-engine test run. Two concurrent suites against one
  Docker daemon collide, because this repo's integration tests use deterministic
  object names (`headspace-<workspace_id>`). Wave file-disjointness says nothing
  about a shared external resource.
- `d4` — h6 holds per-verb, not uniformly: `put` records path+digest in
  `outcome_summary`, `run --input` summarises by file count and total bytes there
  (a multi-file payload cannot list every digest in one line without becoming the
  unbounded blob the result package exists to prevent).
- `d5` — c43 ships half-met; tracked as [#16][i16]. See Drift.
- **A security hole was found in merged code and fixed** — t14, briefed to treat
  t4's implementation as unverified, found that `FINALIZE_WRITE_SCRIPT`'s
  `[ -f "$staged" ]` and `sha256sum` both follow symlinks, so a job sharing the
  volume could swap the staged file for a link, have the digest certify the link's
  target, and get `mv -f` to rename the link into the caller's destination. No
  deviation record covers this: it was a defect in merged work, not a departure
  from the plan. Fixed in `d55fc29` (guard before the hash) and hardened in
  `6a0e635` (re-checked immediately before the rename).
- **The two backends disagreed on what a `ByteSource` is** — t10's conformance
  found `FakeProvider` accepting a bare `bytes` that `DockerProvider` and
  `core/artifacts.py` both refuse, so a call passing against the fake failed
  against a real engine. The fake was the more permissive one, which is the
  dangerous direction. Fixed in `b99e3b6`.
- **Colleague's independent review found a third defect** — `stop()`'s follow-up
  `reload()`/`kill()` could raise `NotFound` when `run` reaps the job container
  after a *successful* graceful stop, reporting failure at the moment the stop
  worked best. Fixed in `5f7ae30`, along with an unmapped exit status.
- **Two docs overclaims were caught and corrected** — README asserted a stopped
  job's status reads `cancelled` (it does not on Docker; see `d5`), and the
  four-surface guarantee was silent about the engine, which reads as a stronger
  claim than we can make. A forwarded `--env` value is readable via
  `docker inspect` under `Config.Env` for the job container's lifetime; README,
  `run --help` and the changelog now say so.
- **`learn`, `overview` and `docs/traceability.md` were stale** — the agent-facing
  discovery surfaces still listed five lifecycle verbs, and traceability still said
  "Staging does not exist" and "Cancellation is a declared category with no
  producer". Corrected in `6ea9194`.

## Remaining Work / Follow-up

- **[#16][i16]** — give the stopped job's own record a `cancelled` status on Docker.
  Needs a cross-process discriminator `stop` can set and `run` can read, and
  `stop` is engine-side-only by design (no lock, no state write), so it cannot be
  a state file. `tests/test_integration_docker.py` asserts the *current* behaviour
  under an `# issue #16` banner, so a fix breaks that test loudly and is told why.
- **[#15][i15]** — deviations `d1`–`d5` are recorded `proposed`. An agent cannot
  confirm its own deviation; they await `devague deviate --confirm d1 d2 d3 d4 d5`.
- **`d3` follow-up** — this repo's live-engine tests use deterministic object
  names, so two concurrent suites collide on one daemon. Worth either namespacing
  them per run or documenting that the integration suite is single-writer.
- **Two live-engine tests are environment-sensitive, and both cost diagnostic
  time here.** `test_h19...` floods 300 MB and can be SIGKILLed under host memory
  pressure (6/6 alone, failed twice under concurrent load). And
  `test_regression_an_allocation_over_the_ceiling_exits_eight...` failed once on
  a CI runner with `exit 6, expected 8` — it needs Docker to report
  `State.OOMKilled: true`, which depends on cgroup version and host pressure, and
  `docker.py`'s own docstring already documents that exit 137 without that flag is
  indistinguishable from a deliberate `SystemExit(137)`. Both predate this branch
  (0.9.0), neither touches code this branch changed, and both pass on re-run
  (the CI job passed on rerun; the test passed 3/3 locally). Worth making them
  robust or explicitly marking them environment-dependent — a suite where a green
  run and a red run mean the same thing trains people to ignore red.
- **`cicd status` under-reports SonarCloud issues** — it showed 0 while the API
  showed 29, and `cicd await` gates on that count. A gate that under-reports is
  worse than no gate: it turns "unchecked" into "verified". Worth fixing in the
  skill.
- **Issue #10 (read-path ancestor symlink) remains open** — a recorded non-goal of
  this frame. The write path does *not* share the hole (`t14`, 9 tests), but the
  read path's guard still inspects only the final tar entry.
- **`put_archive` follows a symlinked ancestor and reports success** — probed live
  and recorded in `tests/test_integration_docker.py`. Defense-in-depth
  documentation only: headspace never hands `put_archive` a caller-controlled
  path. Worth knowing if that ever changes.
