# Build Plan — file-in path (#14)

slug: `file-in-path-14` · status: `exported` · from frame: `file-in-path-14`

> headspace gains a file-in path: a copy-in that mirrors export's discipline, so a network-disabled workspace can receive a non-trivial payload (issue #14)

## Tasks

### t1 — Provider seam: inbound write verb, env on run, stop signature (providers/base.py)

- instruction: Signature + docstring work only — no behavior. Mirror read()'s docstring style at base.py:968 (liveness contract, boundary contract, what raises what). env defaults to an empty mapping so the closed posture is structural.
- covers: c2, c26, c42
- acceptance:
  - the protocol declares write (ByteSource in, digest-verified), run's env mapping (closed default), and stop, each with a docstring stating liveness and boundary contracts
  - a dummy provider lacking any of the three fails the runtime protocol check in a unit test

### t2 — Host-side input model: expansion, digest-during-stream, budget precheck (new headspace/core/inputs.py)

- instruction: Pure host-side module, no engine imports (respect core/`__init__.py` layering). Reuse artifacts.py's chunked digest-during-read discipline; never buffer a whole file. Budget precheck runs before any provider call.
- covers: c7, h7, c8, h8, c15, h12
- acceptance:
  - a directory expands to a sorted, deterministic per-file list; each file is read exactly once while its sha256 and size are computed
  - a payload exceeding remaining `storage_bytes` is refused before any provider call, with a taxonomy exit code and a remediation naming the budget
  - the recorded digest equals an independent sha256sum of the source; the manifest equals the file set exactly

### t3 — Fake provider: inbound write, env observation, stoppable scripted jobs (providers/fake.py)

- instruction: The fake is the conformance twin — implement the seam verbs honestly over `_Workspace`.files, don't shortcut through `write_file`. A scripted in-flight job needs to be stoppable for t10's stop coverage.
- covers: c4, h4
- acceptance:
  - the fake implements all three seam verbs over `_Workspace`.files; `write_file` stays untouched and unused by conformance
  - a scripted job exposes the env it observed; a scripted in-flight job can be stopped

### t4 — Docker inbound: staging, prepare/finalize execs, engine-side digest re-verify, overwrite guard, toolset preflight (providers/docker.py)

- instruction: The hard one. Staging path under a reserved prefix inside the volume; prepare exec creates + preflights tools; `put_archive` targets staging only; finalize exec re-hashes, realpath-checks the destination parent against the volume root, honours the overwrite refusal, then renames. Never trust engine-side path resolution.
- depends on: t1
- covers: c3, c16, c17, c31, c33, c39
- acceptance:
  - `put_archive` lands bytes only in a prepare-exec-created staging path; the finalize exec re-hashes, verifies the resolved destination inside the volume, refuses an existing destination without force, then renames
  - a stopped anchor yields an honest taxonomy classification naming the anchor; the preflight names the profile when a required tool is missing
  - no helper container is ever created: the engine object list before and after a put is identical

### t5 — Docker env threading and stop signal (providers/docker.py)

- instruction: Small and surgical on docker.py after t4 lands. env goes to container environment kwargs only. stop signals by label lookup and must not touch ~/.headspace — the runner stays the single state writer.
- depends on: t4
- covers: c38, c42
- acceptance:
  - the env mapping lands only in the job container's environment kwargs, never in labels or command
  - stop finds the `ROLE_JOB` container by labels, stops then kills, and touches nothing under ~/.headspace

### t6 — Orchestrator put: `INTENT_PUT` journal, non-blocking lock, inputs ledger, reconciliation branch (core/workspace.py)

- instruction: Model on export() at workspace.py:683. New `INTENT_PUT` constant, journal before engine, non-blocking lock like destroy (805), inputs ledger key distinct from artifacts, and a `_reconcile_one` branch mirroring `_reconcile_export`. Check the version-skew question (risk r2) while touching state.json shape.
- depends on: t1, t2
- covers: c5, h5, c6, c32, h27, c36, h31, c40, h35
- acceptance:
  - the journal shows the put intent opened before any engine call and settled or abandoned on every exit path; guards evaluate after lock acquisition
  - a put during a running job refuses immediately, naming the job and pointing at stop
  - copied-in files land in an inputs ledger distinct from artifacts (destroy guard unaffected); provenance and intent payloads carry path+sha256, never contents
  - a copy-in killed mid-flight is settled by the next verb's reconciliation, staging residue reaped, workspace usable

### t7 — run flags: --input, --env, --env-file wiring and name-only recording (core/workspace.py + cli/`_commands`/run.py)

- instruction: run --input must call the same orchestrator function put does — one implementation site is the acceptance bar. Flags go before the workspace id (REMAINDER bargain). Record names/paths/digests only.
- depends on: t6
- covers: c14, c24, c25, c27, c29, c34, h15, h18, h29, c37
- acceptance:
  - --env resolves from the caller's environment at parse time, refusing an unset name; --env-file refuses malformed lines; --input NAME is validated by `require_workspace_path` before any engine contact
  - recording carries env names (and env-file path) only; the no-flag probe from issue #13 is pinned by a regression test
  - run --input drives the same orchestrator copy-in function as put — one implementation site
  - run --help states the job-echo edge: a job that prints its environment writes the value into captured output

### t8 — stop verb: preview default, --apply gate, operator-stopped outcome (core/workspace.py + new cli/`_commands`/stop.py)

- instruction: Preview-by-default is the safety property: no --apply means no engine mutation at all. Pick the operator-stopped exit code against README's 0-8 table and document it there — flag the choice in the PR body (risk r1).
- depends on: t7
- covers: c41, h36, c43
- acceptance:
  - stop without --apply lists the in-flight job (id, command, wall-clock spent) and provably changes nothing; with --apply the job ends and the workspace returns to ready
  - the stopped job's outcome is a distinct operator-stopped status, not `computation_failed` or `infrastructure_failure`, with its exit code documented in README's taxonomy table
